Vectorless RAG evaluation and implementation guide for fintech forensic analysis

Your signals: Polars + DuckDB + FalkorDB, entity recognition, large financial datasets, tax evasion forensics.

Strong yesVectorless RAG suits your domain
Financial forensics is a structured-entity problem. You're asking "what transactions link entity A to entity B via shell company C" — not "find me documents that feel semantically similar to this query." Graph + SQL retrieval is strictly better for this.
Native fitDuckDB = your vectorless retriever
DuckDB on Polars DataFrames can do BM25 full-text search (fts extension), structured filters, and window functions to surface suspicious patterns. No embedding model needed — queries are SQL, latency is milliseconds, and large files parse chunk-by-chunk via read_parquet streaming.
Native fitFalkorDB = graph retrieval layer
Entity relationships are the signal in tax evasion detection. FalkorDB's Cypher queries are vectorless by definition — you traverse the entity graph by relationship type, not embedding distance. This is where you find layered shell company chains, circular ownership, and beneficial owner hiding.
Only ifAdd vectors only for unstructured text
If you have raw document text (email threads, filing narratives, legal descriptions) that you need to query semantically, a lightweight embedding on just those fields is justified. Don't embed your transaction rows — that's wasteful and noisy.
Traditional vector RAG
✓ Great for free-text, fuzzy semantic queries
✗ Expensive on large structured datasets
✗ Hallucination risk on numeric/entity data
✗ Doesn't understand "entity = same person, different aliases"
✗ No native graph traversal
Vectorless RAG your case
✓ Deterministic — results are auditable (critical for forensics)
✓ DuckDB handles millions of rows, sub-second
✓ FalkorDB traverses entity relationships natively
✓ Polars chunked scan for large files without OOM
✓ Zero embedding cost, zero vector index maintenance

Layer 1 — data ingestion (Polars)
Use pl.scan_parquet() / pl.scan_csv() (lazy scanning) so large files never fully load into memory. Apply your entity recognition on streamed chunks via .pipe() or map_batches(). Push resolved entities into FalkorDB incrementally.
Layer 2 — structured retrieval (DuckDB)
Register your Polars DataFrames directly: duckdb.register("txns", df). Build a query factory that converts LLM-extracted intent into SQL — suspicious patterns (round-dollar transactions, rapid layering, structuring below reporting thresholds) are easy WHERE clauses. Enable the fts extension for keyword search over narrative fields.
Layer 3 — graph retrieval (FalkorDB)
Model entities as nodes (Person, Company, Account, Transaction) and relationships (CONTROLS, OWNS, TRANSFERS_TO). Use Cypher variable-length paths to find N-hop ownership chains: MATCH p=(a)-[:CONTROLS*1..5]->(b). FalkorDB's in-memory graph makes multi-hop traversal fast even on large entity sets.
Layer 4 — context assembly + LLM
Combine DuckDB results (transaction rows, aggregate stats) + FalkorDB paths (entity chains) into a structured context block. Pass to the LLM with a forensic analyst prompt. Because the context is structured facts, not embedding-retrieved chunks, hallucination risk on entity names and amounts drops sharply.
Polars lazy scan — avoid OOM on large files
lf = pl.scan_parquet("transactions/*.parquet")
result = (
  lf
  .filter(pl.col("amount") > 9000)          # structuring
  .filter(pl.col("amount") < 10000)
  .with_columns(pl.col("entity_id").cast(pl.Utf8))
  .collect(streaming=True)                   # streaming=True for large files
)
DuckDB — register Polars frame, query directly
import duckdb
con = duckdb.connect()
con.register("txns", result)  # zero-copy from Polars Arrow
suspicious = con.execute("""
  SELECT entity_id, SUM(amount) as total,
         COUNT(*) as tx_count,
         MIN(ts) as first, MAX(ts) as last
  FROM txns
  GROUP BY entity_id
  HAVING tx_count > 20 AND total > 500000
  ORDER BY total DESC
""").pl()  # returns Polars DataFrame
FalkorDB — entity graph traversal
from falkordb import FalkorDB
db = FalkorDB().select_graph("entities")

# Find shell company chains up to 5 hops
result = db.query("""
  MATCH p=(suspect:Person)-[:CONTROLS*1..5]->(acct:Account)
  WHERE suspect.flagged = true
  RETURN suspect.name, [n IN nodes(p) | n.name] AS chain,
         length(p) AS depth
  ORDER BY depth DESC
  LIMIT 50
""")
